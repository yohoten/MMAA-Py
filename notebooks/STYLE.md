# Notebook 版式规范

适用于 `notebooks/` 下的全部 `.ipynb`。新增或修改 notebook 时，请按下述规则执行。

## 1. 文件与标题

- 文件名：`NN.主题.ipynb`，`NN` 为两位序号（01—30），序号与句点均为半角。
- 主题使用简洁中文，库名按官方写法：`NetworkX`、`Prophet`、`NeuralProphet`、`AHP`、`TOPSIS`、`ARMA`、`ARIMA`。
- 文件名末尾不留空格，不使用 `—`、`-` 作为分隔符。
- 每个 notebook 只有一个一级标题：`# NN 标题`，标题文本与文件名主题一致。

示例：`01.综合评价法—AHP层次分析法.ipynb` → `# 01 综合评价法：AHP 层次分析法`。

## 2. 顶部元信息

标题下紧接一行元信息，三项固定顺序，使用全角分隔符 `｜`：

```markdown
> **模块**：综合评价 ｜ **数据**：`data/xxx.csv` ｜ **依赖**：numpy、pandas、matplotlib
```

- 模块取自内容地图：综合评价、图论与网络、多元分析、回归分析、动态模型、模糊数学、灰色系统、神经网络、时间序列、关联规则、优化、数值方法、统计推断、机器学习。
- 数据只列 notebook 实际读取的输入文件；无外部数据写“无（内置示例）”。
- 依赖列出代码实际导入的第三方库，最多 5 个，超出用“等”。

## 3. 章节结构

### 实验型（大多数 notebook）

| 层级 | 章节 |
| --- | --- |
| H2 | 1. 问题背景 |
| H2 | 2. 学习目标 |
| H2 | 3. 环境与数据 |
| H2 | 4. 方法与实现 |
| H2 | 5. 小结 |

- “学习目标”“环境与数据”使用无序列表，不再拆成三级标题。
- “方法与实现”之下再展开 `4.1`、`4.1.1` 等小节。

### 讲义型（23、24、25、28、30）

- 按知识主题顺序编号：`## 1.`、`## 2.`……
- 每个主题下使用 `### X.Y`；确有需要时再用 `#### X.Y.Z`。
- 目录类内容统一命名为“内容导览”。

## 4. 标题层级与编号

- 只允许一个 H1（标题），正文从 H2 开始。
- H2：`## n. 标题`；H3：`### n.m 标题`；H4：`#### n.m.k 标题`；H5：`##### n.m.k.j 标题`。
- 同级编号连续，不得跳号；不得出现两个内容相同的标题。
- 标题末尾不加句号、冒号；超过 30 字且带句读的句子降为加粗段落，不作文档标题。

## 5. 文字排版

- 禁止使用 `<span>`、`<font>`、`<div>`、`<p>` 等内联 HTML 控制字号；标题层级由 Markdown 决定。
- 标题前后各留一个空行；正文段落之间留一个空行。
- 无序列表统一用 `-`，有序列表统一用 `1.`；列表项之间不留空行。
- 代码块必须标注语言：Python 用 `python`，Shell 用 `bash`，纯文本用 `text`；围栏必须成对闭合。
- 独立公式使用 `$$ ... $$`，前后留空行；行内公式使用 `$ ... $`。
- 中文正文使用中文标点；代码、变量名、文件名使用反引号包裹，内部使用半角符号。
- 图片使用 `![说明](路径)`，替代文本写清图意，不只写 `image.png`。
- 不使用 `attachment:` 作为图片源。该形式依赖 notebook 内嵌的 `attachments` 数据，复制、导出或清理元数据后极易失效；统一改为 `../data/images/<文件名>.png` 或仓库内的相对路径。
- 暂无配图可用时，用一行占位说明代替破图：`> *原稿配图未随 notebook 保存，此处暂缺。*`，补齐后删除该行。

## 6. 代码与数据

- 数据统一放在仓库根目录 `data/`；notebook 内使用相对路径：

```python
from pathlib import Path
DATA = Path.cwd().parent / "data"      # 内核工作目录为 notebooks/
df = pd.read_csv(DATA / "basketball.csv")
```

- 不修改 `data/` 中的原始文件；中间结果写入各案例的 `output/`（已在 `.gitignore` 中忽略）。
- 保留有意义的执行输出；提交前删除空代码单元、报错堆栈和无关的调试输出。
- 一个 notebook 只解决一个主题，避免把其他章节的内容粘入。

## 7. 提交前检查

1. 文件名与一级标题一致，序号无重复。
2. 顶部元信息的模块、数据、依赖与实际代码一致。
3. 标题编号连续、层级不跳级、无重复标题。
4. 无内联 HTML 残留，代码围栏全部闭合。
5. 代码单元可从上到下运行，数据路径不指向个人机器。
